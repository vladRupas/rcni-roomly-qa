# Результаты проверки формы бронирования

Проверяемая страница: <https://rcsi-science.github.io/demo-roomly/>  
Дата проверки: 25.11.2026  
Объём: ручная проверка в браузере и три теста кандидата на Python + Playwright. Приложение не изменялось.

## Приоритетный чек-лист

| Приоритет | Проверка | Результат |
|---|---|---|
| P1 | Успешная бронь: выбранная комната, будущее расписание, вместимость, имя и почта; сообщение содержит введённые данные | Пройдено вручную и автотестом |
| P1 | Длительность строго от 30 минут до 4 часов; конец позже начала | Не пройдено: 10 минут и 5 часов приняты (BUG-01) |
| P1 | Дата в прошлом запрещена; для сегодняшней даты время начала не прошло | Ограничение даты задано; проверку времени на сегодня код не выполняет, полноценный сценарий не проверялся |
| P1 | Комната обязательна; число участников от 1 до 20 и не превышает вместимость комнаты | Проверка вместимости Малой на 5 участников пройдена автотестом; остальные границы отдельно не проверялись |
| P1 | Обязательны дата, время начала/окончания, участники, имя, рабочая почта | Не все комбинации пустых полей проверялись |
| P1 | Корректный формат электронной почты | Не проверялось в браузере/автотесте |
| P2 | После перезагрузки введённые данные и результат брони не сохраняются | Пройдено автотестом для полей комнаты, имени, почты и статуса |
| P2 | Сообщение об ошибке привязано к полю, введённые данные не теряются | Проверка для превышения вместимости пройдена автотестом |
| P2 | Отображение формы и доступность основных элементов | Основные элементы формы доступны; подробная визуальная и адаптивная проверка не выполнялась |

## Дефекты

### BUG-01 — не проверяются минимальная и максимальная длительность

- **Приоритет:** P1 — нарушает явно заданные правила бронирования; пользователь получает сообщение об успешной броне для неподходящего интервала.
- **Условия:** заполнить все обязательные поля корректно, выбрать «Малая», дату в будущем, 2 участников, имя и валидную почту.
- **Шаги:**
  1. Установить начало 10:00 и окончание 10:10, нажать «Забронировать».
  2. Повторить с окончанием 15:00.
- **Ожидаемый результат:** форма отклоняет оба интервала и сообщает, что длительность должна быть от 30 минут до 4 часов.
- **Фактический результат:** для обоих интервалов отображается «Бронирование создано».
- **Доказательство:** воспроизведено вручную на опубликованной странице 25.11.2026; проверочные тесты в `tests/test_booking.py`. `test_booking_shorter_than_30_minutes_is_rejected` отмечен `xfail(strict=True)` и проверяет требуемое поведение.

### BUG-02 — одинаковое время начала и окончания принимается

- **Приоритет:** P1 — создаётся фиктивная бронь нулевой длительности, что противоречит правилу «окончание позже начала».
- **Условия:** валидно заполнить форму, дата в будущем, выбрать комнату с достаточной вместимостью.
- **Шаги:** указать начало и окончание 10:00, заполнить остальные поля, нажать «Забронировать».
- **Ожидаемый результат:** ошибка на поле окончания; бронь не создаётся.
- **Фактический результат:** сравнение проверяет только `endTime < startTime`, поэтому равные значения не порождают ошибку и проходят к сообщению успеха.
- **Доказательство:** анализ `validate()` в `script.js` (проверка условия окончания времени). Отдельно в браузере не воспроизводилось.

## Вопросы и допущения

1. В каком часовом поясе трактуются дата и время бронирования — локальном браузера или часовом поясе офиса?
2. Как обрабатывать бронь на текущую дату: достаточно запретить прошедшее время или также нужен минимальный интервал до начала?
3. Верно ли, что 30 минут и 4 часа включены в допустимый диапазон? Формулировка «от … до …» трактовалась как включительная.
4. Для ошибки формата почты допускаются ли адреса с `+`, поддоменами и интернациональными символами?
5. Подтвердите, что бронь является демонстрационной: ожидаемое поведение говорит, что сетевой отправки и сохранения быть не должно.

## Проверенные области

- Загрузка опубликованной страницы и доступность формы.
- Позитивная отправка на будущую дату и отображение комнаты, даты, времени и имени.
- Отсутствие сохранения значений после перезагрузки.
- Превышение вместимости выбранной комнаты.
- Слишком короткий и слишком длинный интервалы — вручную.
- Равное время окончания и начала — анализ кода.

## Риски и ограничения

- Страница статическая и демонстрационная; конфликтов расписания, фактической отправки, API, базы данных и интеграций нет в доступном объёме.
- Нет тестирования в разных браузерах, мобильных разрешениях, часовых поясах и на границах смены даты.
- Автотесты используют опубликованную страницу. Результат зависит от доступности GitHub Pages и сети.
- Текущая дата для запуска тестов берётся из системной даты контейнера; тестовые брони назначаются на следующий календарный день.
- Сценарии валидации каждого обязательного поля, полного диапазона вместимости и формата email требуют дальнейшего покрытия.
- Код сравнивает время как строку `HH:MM`; правила интервалов через полночь не описаны и не проверялись.

## Автотесты и запуск

Тесты кандидата:

1. `test_successful_booking_and_no_persistence` — позитивный сценарий и очистка полей после перезагрузки.
2. `test_room_capacity_is_validated` — негативный сценарий превышения вместимости.
3. `test_booking_shorter_than_30_minutes_is_rejected` — ожидаемое поведение для BUG-01; временно ожидаемый провал (`xfail(strict=True)`).

Готовый `test_booking_page_is_available` из каркаса — отдельный smoke-тест и в эти три не входит.

Из корня репозитория:

```bash
docker compose -p roomly-qa run --build --rm tests
```

Параметр `-p roomly-qa` задаёт допустимое имя проекта Compose, потому что папка сдачи называется кириллицей и содержит пробел.

Для страницы или стенда с другим адресом:

```bash
BASE_URL=https://example.test/ docker compose run --build --rm tests
```

Результаты: `artifacts/junit.xml`, скриншоты и trace при сбое — в `artifacts/browser/`.

## Среда, результат и время

- ОС хоста по данным Windows Registry: Windows 10 Home, 25H2, build 26200.9711.
- Docker Desktop Engine: Linux; Docker CLI 28.1.1; Docker Compose v2.35.1.
- Среда контейнера: Python 3.12.3, pytest 8.3.5, Playwright Python 1.64.1, Chromium 156.0.8078.4.
- Команда: `docker compose -p roomly-qa run --build --rm tests`.
- **Итог:** 3 passed, 1 xfailed за 8.82 секунды; unexpected failures нет. Smoke-тест и два теста кандидата прошли. Тест `test_booking_shorter_than_30_minutes_is_rejected` завершился ожидаемым strict XFAIL с причиной `BUG-01: бронирование короче 30 минут принимается`.
- Первый запуск собрал образ за 376 секунд; вместе с тестированием — около 6 минут 25 секунд. На анализ, ручную проверку, подготовку тестов и отчёта до запуска ушло около 25 минут; общее рабочее время — около 31.5 минут.
- Артефакты запуска: `artifacts/junit.xml`; при падениях Playwright сохраняет скриншоты и trace в `artifacts/browser/`.

## Использование ИИ

ИИ использовался открыто для анализа требований и кода страницы, подготовки структуры чек-листа и отчёта, написания черновой версии автотестов и редактирования инструкции. Кандидату следует самостоятельно перечитать изменения, перепроверить выводы и быть готовым объяснить локаторы, ожидания Playwright и `xfail(strict=True)`, а также внести небольшое изменение в тест на встрече.
